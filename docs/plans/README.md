# About the plans in this folder

<!-- Client-facing. Explains what these files are, in plain words. No internal tool names, no review panel detail, no research method. -->

This folder holds the written plan for each feature, prepared by the DevAgent contributors. It is the record of what we agreed to build and how, kept next to the code so the two stay in step.

## The files

| File | What it tells you |
|---|---|
| `01-requirements.md` | What you asked for, who uses it, and how you will decide it is done |
| `02-design.md` | How it is built: architecture, data handling, security, running cost, and how it is tested |
| `05-implementation.md` | The work broken into small tasks, each with the check that proves it |

## How to read them
- Start with the requirements, then the design.
- `status` at the top of each file says whether it is a draft, approved, or as-built.
- The design ends with a change log: every change after the first draft, with its reason.
- In the implementation plan, a task marked `[x]` has passed its check; `[ ]` has not started.

## What to look for
- The "Open decisions" list in the design: items that need an answer from you.
- The risk register ({{risk_register_location}}): open and accepted risks, each with a named owner.
